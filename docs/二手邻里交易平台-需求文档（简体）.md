# 二手邻里交易平台需求文档

## 1. 项目概述

### 1.1 项目目标
建设一个具备会员门槛的 C2C 二手交易平台，优先服务同栋大厦或同屋苑住户之间的交易需求，并通过帖子有效期机制保证信息的新鲜度。

### 1.2 适用场景
- 用户发布二手家具、电器等闲置物品。
- 买家优先发现同栋大厦或邻里范围内的商品。
- 登录会员通过 WhatsApp 或站内聊天联系卖家。

## 2. 业务规则

### 2.1 帖子有效期
- 每个帖子默认有效期为 `14 天`
- 到期后系统自动将帖子状态变更为 `Expired`
- 过期帖子从前台搜索结果中隐藏

### 2.2 续期规则
- 卖家可在后台查看已过期帖子
- 点击“重新发布”后：
  - 帖子有效期重置为新的 `14 天`
  - 帖子重新排到首页靠前位置
  - 用户应可同时修改价格或图片

### 2.3 邻里隐私规则
- 用户注册时需选择所属大厦或屋苑
- 商品可配置为以下可见范围：
  - `Public`：全站用户可见
  - `Building-Only`：仅同大厦认证会员可见

### 2.4 会员权限规则
- 访客仅可浏览商品信息
- 未登录用户不可查看 WhatsApp 按钮，也不可发起站内聊天
- 点击联络按钮时，系统需引导至注册或登录页面

## 3. 用户角色

### 3.1 卖家
- 发布二手物品
- 设置可见范围和联络方式
- 管理帖子续期与沟通记录

### 3.2 买家
- 浏览商品列表与详情页
- 登录后联系卖家
- 在邻里模式下查看同大厦限定商品

### 3.3 平台系统
- 管理帖子生命周期
- 管理可见范围和会员权限
- 提供聊天与消息通知机制

## 4. 核心功能需求

### 4.1 商品发布
- 用户可发布二手家具或电器信息
- 支持设置标题、分类、价格、新旧程度、尺寸、描述、交收地点和图片
- 支持设置商品可见性为公开或仅同大厦可见

### 4.2 双轨沟通系统

#### 卖家可选联络方式
- 显示 WhatsApp
- 开启站内短讯
- 同时开启两者

#### 买家侧交互
- 登录会员点击 WhatsApp 后跳转外部 WhatsApp
- 登录会员点击站内短讯后打开聊天窗口
- 若未登录，统一跳转登录页

### 4.3 WhatsApp 联系
- 使用协议：`https://wa.me/{phone}?text={encoded_message}`
- 预设消息中自动包含：
  - 商品标题
  - 商品链接

### 4.4 站内聊天
- 提供基础文字对话功能
- 支持新消息红点通知
- 聊天记录需持久化存储

### 4.5 帖子管理
- 卖家可查看帖子状态
- 支持重新发布过期帖子
- 平台仅执行软删除，不直接物理删除数据

## 5. 商品详情字段要求

### 5.1 基本信息
- 标题
- 分类
- 价格，支持“面议”或“免费送赠”
- 新旧程度

### 5.2 规格说明
- 尺寸，建议必填，包括长、宽、高
- 详细描述，例如使用情况、保养信息、损坏说明

### 5.3 交收信息
- 地区，采用香港 18 区下拉选择
- 具体地点，例如地铁站、屋苑自取
- 搬运要求，例如是否需自行拆卸、是否有电梯、是否需走楼梯

### 5.4 联系与权限信息
- 电话
- WhatsApp
- 站内短讯
- 联系方式仅对会员可见

### 5.5 通用字段
- 多图上传
- 封面图设置
- 发布者身份，标记为“业主”或“代理人/专业卖家”
- `status`：`Active / Expired / Sold`
- `created_at`
- `updated_at`
- `expire_at`

## 6. 数据库结构要求

### 6.1 用户表
`Users`
- `id`
- `phone`
- `building_id`
- `is_member`

### 6.2 商品表
`Items`
- `id`
- `seller_id`
- `title`
- `dimensions`
- `contact_method`，枚举值：`WhatsApp / Chat / Both`
- `expire_at`

### 6.3 会话表
`Chats`
- `id`
- `item_id`
- `buyer_id`
- `seller_id`
- `last_message`
- `updated_at`

### 6.4 消息表
`Messages`
- `id`
- `chat_id`
- `sender_id`
- `content`
- `timestamp`

## 7. 技术要求

### 7.1 通讯逻辑
- WhatsApp 跳转链接需按标准协议生成
- 站内聊天需支持基础即时通信能力
- 新消息状态需可追踪并展示通知

### 7.2 安全与隐私
- 后端 API 必须校验 Auth Token
- 获取卖家联系方式的请求必须来自已登录会员
- 禁止通过未授权接口批量抓取 `whatsapp_num`

### 7.3 定时任务
- 系统每小时扫描数据库
- 将已过期帖子状态更新为 `Expired`
- 保留历史记录，仅执行软删除，例如 `is_deleted = true`

## 8. 用户流程

### 8.1 买家联系流程
1. 浏览商品详情页
2. 点击“联络卖家”
3. 若未登录，跳转登录或注册页面
4. 登录后根据卖家开启的联络方式发起联系

### 8.2 卖家续期流程
1. 在后台查看已过期商品
2. 点击“重新发布”
3. 可同步修改价格或图片
4. 提交后重置 `expire_at`
5. 商品重新进入前台展示

## 9. 验收标准

### 9.1 功能验收
- 未登录状态点击“联络卖家”时，应成功跳转至登录页面
- 帖子到期 14 天后应从首页消失
- 卖家可成功续期过期帖子
- 若卖家只开启“站内短讯”，买家侧不应显示 WhatsApp 按钮
- 非同大厦会员不可查看“邻里限定”商品

### 9.2 技术验收
- 站内消息需正确入库
- 新消息红点提醒正常
- 过期任务执行后状态字段准确更新

## 11. 基于参考页面的优化点

### 11.1 可借鉴的页面特征
- 参考页面的二手物品首页具备较完整的分类、价格、成色、地区和排序筛选结构，便于用户快速缩小范围。
- 列表卡片直接展示标题、简述、发布时间、价格、分类和地区，适合高频浏览型交易场景。
- 页面支持“愿意捐赠”这类特殊价格表达，对低价和赠送类物品的转化很有帮助。

### 11.2 本项目建议优化方向
- 将“邻里优先”做成顶部显性筛选开关，例如“仅看同大厦”“仅看可自提”“仅看免费送赠”。
- 列表卡片中建议强化尺寸信息展示，尤其在家具、电器类目中把长宽高或容量作为核心字段外显。
- 增加“交收方式标签”，例如“自提”“可送货”“需搬楼梯”“有电梯”，减少无效沟通。
- 增加“邻里限定”视觉标识，并在卡片中标注楼栋或屋苑级可见性，提高社区交易氛围。
- 对免费送赠、急售、今日更新等场景增加徽标，提升信息流点击率。
- 发布流程中增加“快速发布模板”，优先适配床架、雪柜、洗衣机、沙发等高频类目。
- 在联系前增加“安全提示”和“交易提醒”，例如线下交收建议、预约时间建议和防诈骗提醒，提高平台可信度。

## 12. 与统一页面的关系说明
- 本模块适合作为统一频道页中的“邻里交易”子频道。
- 入口页应突出“同屋苑优先”和“低摩擦交易”定位，与楼盘放售、服务式住宅形成明显区分。
- 在统一页面中，本模块更偏高频、轻决策、强地理关系链场景。
