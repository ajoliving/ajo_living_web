# AJO Living Public UI Style Prompt

## 使用範圍

本文件用於 AJO Living 公開入口與公開查詢頁，包括首頁、樓盤放售、服務式住宅、二手傢俬、超市優惠，以及後續相近的公開列表、詳情、搜尋與篩選頁。

AJO Living 是面向物業管理公司、住戶、業主、租客與訪客的物業管理主系統，不是單一 marketplace、樓盤展示站或優惠內容站。公開頁只承擔清楚入口、正式展示、查詢與轉換操作，不承擔管理後台的完整營運能力。

## 可直接使用的 Prompt

請依照 AJO Living 公開頁 UI 基線建立頁面。整體風格保持正式、乾淨、可信任、可正式上線，像一個香港物業管理主系統的公開入口與查詢工具，而不是一般 marketing landing page、社群 feed 或概念稿。所有介面文案使用繁體中文，品牌名稱 AJO Living 保持英文；不要使用表情符號，不要加入開發說明、設計說明、流程提示或舞台感文案。

頁面要以真實業務內容為中心：首頁呈現平台入口；樓盤放售與服務式住宅呈現可搜尋、可篩選、可查看詳情的物業列表；二手傢俬呈現屋苑生活二手物品列表；超市優惠呈現商品格價、優惠、收藏與詳情查詢。不要把不同業務混成同一個 marketplace 語義，必須保留各自的模組名稱、資料欄位與操作目的。

## 整體風格

1. 風格定位
   - 正式、簡約、清楚、克制。
   - 以查詢效率、資訊密度與可讀性為優先。
   - 不做大段品牌宣傳，不使用誇張裝飾，不用空泛 slogan。
   - 頁面要看起來像可直接交付給香港物業公司、住戶與訪客使用。

2. 視覺基線
   - 背景以白色、暖灰、淺米灰與非常淡的 tint 為主。
   - 表面使用白色或接近白色，配合細邊框與極輕陰影。
   - 主色使用 AJO 既有暖銅色或低飽和深色作為行動與選中狀態，不要讓整頁被單一色相支配。
   - 可使用少量低飽和綠、灰藍、深墨綠、暖銅作為狀態與分類輔助色。
   - 避免大面積紫色、藍紫漸層、深藍 slate、棕橙 espresso、米色砂色單一主題。

3. 圖片使用
   - 首頁、樓盤、服務式住宅、傢俬必須使用真實圖片或可辨識的實物圖片。
   - 圖片要能看清產品、物業、空間或物件，不使用模糊、抽象、暗色氛圍圖作為主要內容。
   - 列表卡片圖片使用 `object-cover`，無圖時使用淺灰占位與 picture icon。
   - 圖片圓角保持克制，建議 8px 至 12px；不要做過大圓角。

## 版面基線

1. 頁面容器
   - 公開列表頁最大寬度使用既有 `--layout-page-max-width`，約 92rem。
   - 桌面 padding 使用 24px 至 32px，手機使用 16px 至 20px。
   - 頁面頂部不要堆疊大型說明區；列表與工具頁應優先露出搜尋、篩選與結果。
   - 區塊之間使用清楚留白，不用巢狀卡片包卡片。

2. 首頁
   - 首屏可以更具品牌感，但仍要保持正式入口屬性。
   - 第一視覺應讓使用者知道這是 AJO Living 及其主要業務入口。
   - 可使用全寬實景圖片、輪播或沉浸式首頁視覺；不要用左右圖文 marketing hero。
   - 首頁文案只保留必要的定位與入口，不寫設計意圖、過場說明或給實作者看的文字。
   - 首頁入口至少清楚指向二手傢俬、樓盤放售、服務式住宅、支付或其他已上線核心模組。

3. 樓盤放售與服務式住宅
   - 採用公開列表頁結構：篩選條件、排序、結果數、卡片列表、詳情入口。
   - 樓盤放售重點資訊為地區、物業類型、出售或出租、價格、面積、房數、裝修、發布者身份、收藏與比較。
   - 服務式住宅重點資訊為地區、月租或日租、面積、配套、入住條件、詳情入口。
   - 二者可以共享列表樣式，但頁面文案和篩選欄位必須符合各自業務，不要混寫。

4. 二手傢俬
   - 採用商品篩選頁結構：分類、價格、成色、可見範圍、地區、搜尋、排序與展示模式。
   - 桌面可使用頂部緊湊篩選列加結果列表，右側可保留廣告欄。
   - 商品卡片需要顯示圖片、地區、分類、成色、標題、摘要、價格、發布時間、收藏與詳情入口。
   - 視覺要像正式生活服務列表，不要像社交動態。

5. 超市優惠
   - 採用工具型查詢頁結構：左側分頁導覽或上方 tab，右側主內容。
   - 首頁提供搜尋、熱門分類、摘要數據與優惠參考。
   - 篩選與優惠分頁以表格或緊湊列表為主，商品卡片作為輔助視圖。
   - 詳情頁重點呈現商品名稱、品牌、最低價商店、優惠、價格走勢、門店與收藏提醒。
   - 文案保持查詢語義，例如「商品格價」「優惠商品」「價格只供參考」，不要使用促銷口吻。

## 元件規則

1. 篩選區
   - 桌面優先使用清楚的篩選面板或緊湊篩選列。
   - 篩選項用 pill、checkbox、select、toggle 或搜尋框，不用純文字假按鈕。
   - 已選狀態必須有明確背景、邊框與文字顏色。
   - 手機版篩選可折疊，打開後不要遮住主要操作。

2. 搜尋與排序
   - 搜尋框左側使用 search icon，按 Enter 或搜尋按鈕提交。
   - 有 autocomplete 時只顯示實際建議，不顯示教學說明。
   - 排序 select 放在結果工具列右側；窄屏允許換行。
   - 結果數與 active filters 應清楚顯示，但不要過度突出。

3. 卡片
   - 卡片圓角建議 8px 至 12px，邊框 1px，陰影非常輕。
   - 卡片內資訊層級固定：圖片、meta、標題、摘要或核心規格、價格、操作。
   - 操作入口要明確，例如「查看詳情」「收藏」「比較」。
   - 不要把卡片做成過度裝飾的浮動玻璃效果。

4. 表格
   - 價格、優惠、商品比較等高密度資訊優先使用表格。
   - 表頭使用淺色背景或底部分隔線。
   - 行 hover 可以有非常淡的背景變化。
   - 手機版表格可改為卡片或橫向滾動，但文字不可重疊。

5. 按鈕與 icon
   - 主要操作使用實心主色按鈕。
   - 次要操作使用白底或透明底細邊框。
   - 工具操作優先使用 icon button，必須有 `aria-label` 和 hover tooltip。
   - 常見操作使用 familiar icon，例如 search、star、trash、layout-grid、arrow-left、arrow-right、picture、location。

## 字體與文字

1. 字體
   - 使用現有 token：`--font-sans` 作為一般文字，`--font-display` 只用於首頁主標、頁面主標或重要數字。
   - 列表頁標題不要過大，避免壓過篩選與結果。
   - 不使用 viewport width 直接縮放字級。
   - letter spacing 保持 0；只有小型 uppercase label 可使用 0.08em 至 0.14em。

2. 文案語氣
   - 繁體中文，正式、直接、可執行。
   - 可用：「查看詳情」「搜尋」「重設篩選」「全部地區」「價格只供參考」「已收藏」。
   - 不用：「打造沉浸體驗」「建立氣氛」「高級感」「下面再把模組說清楚」「之後的模組區」。
   - 不要在頁面上解釋功能如何設計或為什麼這樣設計。
   - 不要出現開發階段、原型、mock、stage、wireframe 等面向實作者的詞。

3. 語言
   - 介面文案使用繁體中文。
   - 品牌、API 欄位、路由、元件名、程式碼識別符可保持 English。
   - 不使用簡體中文作為檔案內容或 UI 文案。

## 色彩建議

優先使用專案既有 token，不硬編碼新色：

```css
--color-canvas: 255 255 255;
--color-page-tint: 248 248 245;
--color-surface: 255 255 255;
--color-surface-muted: 250 250 248;
--color-surface-raised: 255 255 252;
--color-primary: 168 129 82;
--color-primary-soft: 241 234 224;
--color-text: 34 34 38;
--color-text-muted: 96 96 104;
--color-border: 230 230 232;
--color-success: 46 132 100;
--color-warning: 188 135 78;
--color-danger: 178 77 73;
```

若需要補充色，只能作為小面積狀態、圖表或 badge 使用，並確保與主色不衝突。

## 響應式要求

1. Desktop
   - 首頁可以使用沉浸式首屏。
   - 列表頁優先使用兩欄或工具列加列表布局。
   - 樓盤與傢俬卡片可使用 2 至 3 欄 grid。
   - 優惠頁可使用 sidebar 加內容區，表格優先。

2. Tablet
   - 篩選欄可上移為橫向工具列或變成可折疊面板。
   - 卡片 grid 改為 2 欄。
   - 廣告欄或次要 side rail 可下移。

3. Mobile
   - 頁面改為單欄。
   - 篩選入口使用明確按鈕，已選數量可顯示在按鈕旁。
   - 卡片單欄，圖片比例穩定，文字不能溢出。
   - 表格若無法完整閱讀，改成商品卡片或允許橫向滾動。

## 禁止事項

- 不使用表情符號。
- 不使用簡體中文作為 UI 文案或文件內容。
- 不把公開頁做成 SaaS marketing landing page。
- 不使用大段說明、設計講解、開發提示或面向實作者的文案。
- 不使用抽象漸層、orb、bokeh 作為主要視覺。
- 不把頁面所有能力堆進同一個 marketplace 語義。
- 不在卡片內再包一層裝飾卡片。
- 不使用過大的圓角、過重陰影或過度玻璃擬態。
- 不讓文字、按鈕、價格、badge 在手機或桌面重疊。

## 交付檢查

交付 UI 前需確認：

1. 首屏能立即看出頁面所屬模組與主要操作。
2. 搜尋、篩選、排序、結果、空狀態、載入狀態都可辨識。
3. 卡片與表格資訊層級清楚，價格與狀態不被裝飾壓過。
4. Desktop、tablet、mobile 三種寬度下文字不溢出、不重疊。
5. 介面沒有表情符號、簡體中文、開發說明或舞台感文案。
6. 視覺仍符合 AJO Living 既有 token 與公開頁風格。
