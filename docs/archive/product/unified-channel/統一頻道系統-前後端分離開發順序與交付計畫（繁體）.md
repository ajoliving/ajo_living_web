## 2. 當前決策基線

### 2.1 一期只做單一業務模組
- 一期只實作 `二手鄰里交易平台`。
- `服務式住宅展示與詢盤平台`、`樓盤放售頻道` 只保留未來擴展位，不進入本輪開發。

### 2.2 採用前後端分離
- 前端專案目錄：`web`
- 後端專案目錄：`http_service`
- 前端僅負責畫面、互動、狀態與 API 串接。
- 後端負責資料、權限、上傳、聊天、生命周期與定時任務。

### 2.3 前端先做高保真原型，但直接落在正式工程
- 不另外建立純 `HTML/CSS/JS` 原型專案。
- 高保真原型直接在 `web` 專案中實作，避免原型完成後全部重寫。
- 前端先用 mock data 跑通主要頁面與互動，再逐步切換為真實 API。

### 2.4 技術基線
- 前端：`Vue 3 + TypeScript + Vite + Pinia + Tailwind CSS + Axios`
- 前端元件庫：`Ant Design Vue 4`
- 多語系：`vue-i18n`
- 後端：`Go + Gin + GORM + PostgreSQL`
- 檔案儲存：阿里雲 `OSS`
- 反向代理：`Nginx`
- 部署方式：`Docker Compose`

### 2.5 設計系統優先於業務頁面細節
- 前端需先建立主題 token 與多主題切換能力。
- 前端需先建立 `zh-HK` 與 `en` 的 i18n 骨架。
- 頁面開發不可先把顏色、字體、間距寫死在元件中。

## 3. 一期範圍與非一期範圍

### 3.1 一期必做
- 會員登入與基本資料
- 所屬屋苑或大廈選擇
- 二手物品列表頁
- 二手物品詳情頁
- 二手物品發布頁
- 我的發布
- 聯絡方式權限控制
- 站內聊天
- 圖片上傳
- 帖子過期與重新發布
- 基礎多主題能力
- i18n 骨架

### 3.2 一期不做
- 服務式住宅完整功能
- 樓盤放售完整功能
- AJO Point 積分與支付
- 問盤郵件系統
- 收藏、推薦、相似房源
- 搜尋引擎或 Elasticsearch
- 營運後台與審核後台

## 4. 總體開發原則

### 4.1 先骨架，再原型，再契約，再串接
- 先起前後端工程骨架。
- 再由前端完成高保真原型與設計系統。
- 再凍結欄位、狀態、互動與 API 契約。
- 最後接入真實後端能力。

### 4.2 前端不等待後端才開始
- 前端先用 mock data 完成畫面與互動。
- 後端同步完成基礎服務與資料模型。
- 真實 API 就緒後，前端逐頁替換資料來源。

### 4.3 後端不等前端全部畫完才開始
- 後端先完成系統骨架、配置、資料庫、錯誤碼、中間件、健康檢查。
- 原型與欄位穩定後，優先實作最短閉環的核心接口。

### 4.4 每個階段只解決一類主要問題
- 設計階段解決畫面、主題、文案與互動。
- 契約階段解決欄位、狀態與接口。
- 開發階段解決實作與聯調。
- 測試階段解決缺陷與驗收。

## 5. 分階段開發順序

### 階段 0：專案骨架初始化

#### 前端工作
- 在 `web` 建立 `Vue 3 + TypeScript + Vite` 專案。
- 接入 `Pinia`、`Vue Router`、`Axios`、`Tailwind CSS`、`Ant Design Vue 4`、`vue-i18n`。
- 建立基礎目錄：`httpapis`、`model`、`pinia`、`router`、`stores`、`utils`、`components`、`views`。
- 建立全域 Layout、路由骨架、空白首頁與基礎 404 頁。

#### 後端工作
- 在 `http_service` 建立 `Go` 專案與 `go.mod`。
- 建立 `cmd/server`、`internal/router`、`internal/handler`、`internal/service`、`internal/model`、`internal/middleware`、`internal/config`、`internal/database`、`internal/errcode`、`internal/logger`、`internal/utils`。
- 接入 `Gin`、`GORM`、`PostgreSQL` 驅動、設定讀取、基礎 logger、request id、中介層骨架。
- 建立 `/api/v1/health` 健康檢查接口。

#### 交付物
- 前端可成功啟動開發環境。
- 後端可成功啟動服務並回傳健康檢查結果。
- `.env.example`、本地啟動說明、Docker Compose 基礎檔案。

### 階段 1：前端設計系統與高保真原型先行

#### 前端工作
- 建立設計 token：`color`、`radius`、`shadow`、`spacing`、`font`、`border`。
- 至少建立三套主題：`default`、`warm`、`dark-neutral` 或其他明確主題組合。
- 建立主題切換機制，支援全站切換。
- 建立 `zh-HK` 與 `en` 的 i18n 檔案骨架。
- 用 mock data 完成一期核心頁面高保真原型：
  - 統一入口頁
  - 二手列表頁
  - 二手詳情頁
  - 發布頁
  - 我的發布頁
  - 聊天頁
  - 登入頁
- 完成 desktop 與 mobile 的響應式版面。

#### 後端工作
- 同步整理一期資料模型與欄位清單。
- 依據需求文檔與 ERD，完成 users、profiles、communities、listings、secondhand_listings、listing_contacts、media_assets、listing_images、chats、messages 的表結構草案。
- 整理一期 API 草案與狀態枚舉草案。

#### 交付物
- 可演示的前端高保真原型。
- 可確認的欄位與狀態清單。
- 後端資料表草案與接口草案。

#### 階段門檻
- 主題風格、字體層級、卡片樣式、按鈕樣式、表單樣式需先定稿。
- 二手一期頁面資訊架構先凍結，不再邊做邊改頁面結構。

### 階段 2：接口契約與資料模型凍結

#### 前端工作
- 依原型整理每一頁所需欄位、互動事件、空狀態、錯誤狀態與權限狀態。
- 為每個頁面標註 API 依賴與資料來源。
- 建立前端 TypeScript 資料型別草稿。

#### 後端工作
- 凍結一期資料模型。
- 凍結一期 API 契約，至少覆蓋：
  - `auth`
  - `me`
  - `communities`
  - `uploads`
  - `secondhand listings`
  - `contact access`
  - `chats`
  - `messages`
  - `republish`
- 凍結錯誤碼口徑與統一回應格式。

#### 交付物
- 一期 API 契約定稿。
- 一期資料表與欄位定稿。
- 前端頁面欄位對照表。

#### 階段門檻
- 此階段結束後，不再隨意新增欄位與頁面流程。
- 若有變更，必須同步修改需求文檔、API 文檔與前端型別。

### 階段 3：後端基礎能力實作，前端保留 mock 流程

#### 前端工作
- 抽離 API 層與 mock data 層，確保後續可平滑切換。
- 完成共用元件：
  - Header
  - 搜尋列
  - 篩選列
  - 列表卡片
  - 圖片上傳元件
  - 聯絡入口模組
  - 聊天訊息氣泡
- 繼續優化視覺細節與互動節奏，不接真實 API。

#### 後端工作
- 實作配置讀取、資料庫初始化、logger、errcode、中介層、基礎路由。
- 完成資料表 migration。
- 實作會員登入基礎流程：
  - OTP 請求
  - OTP 驗證
  - 取得當前會員資料
  - 更新會員資料
- 實作社區資料查詢接口。

#### 交付物
- 後端基礎服務骨架完成。
- 登入與會員資料接口可用。
- 前端原型元件化完成，可等待接 API。

### 階段 4：二手交易核心閉環實作

#### 前端工作
- 先接入以下真實 API：
  - 登入
  - 會員資料
  - 社區清單
  - 二手列表
  - 二手詳情
- 保留發布、聊天與聯絡流程的 mock 版本，避免阻塞。

#### 後端工作
- 實作二手交易核心接口：
  - 建立帖子
  - 編輯帖子
  - 列表查詢
  - 詳情查詢
  - 我的發布
  - 軟刪除
- 接入阿里雲 `OSS` 上傳流程：
  - 上傳憑證
  - 上傳完成回寫
  - 圖片資產落庫
- 完成 `building_only` 與 `public` 可見性邏輯。

#### 交付物
- 二手列表、詳情、我的發布頁已接真實資料。
- 後端完成二手一期最核心 CRUD 與上傳流程。

#### 階段門檻
- 發布成功後需能在列表與詳情頁看到真實資料。
- 未登入與非權限會員的可見性行為需可驗證。

### 階段 5：聯絡方式與站內聊天

#### 前端工作
- 接入 `contact access` 接口，控制電話、WhatsApp、聊天入口的顯示與行為。
- 將聊天頁與詳情頁聊天入口切換為真實會話。
- 完成聊天列表、會話詳情、未讀提示與空狀態處理。

#### 後端工作
- 實作聯絡方式權限接口。
- 實作會話建立或復用接口。
- 實作訊息列表與發訊息接口。
- 實作未讀數與已讀狀態的基礎能力。
- 保證 `building_only`、會員身份、帖子狀態在聊天與聯絡流程中被再次校驗。

#### 交付物
- 詳情頁聯絡流程可閉環。
- 站內聊天主流程可閉環。

### 階段 6：生命周期、重新發布與營運穩定性

#### 前端工作
- 接入帖子狀態顯示。
- 接入過期帖子重新發布流程。
- 在我的發布頁顯示 `active`、`expired`、`sold` 等狀態。

#### 後端工作
- 實作過期掃描定時任務。
- 實作重新發布接口，重置 `expire_at` 並刷新排序時間。
- 補齊軟刪除、狀態轉移、防呆與必要日誌。

#### 交付物
- 過期後列表隱藏規則正確。
- 重新發布後排序與有效期正確。

### 階段 7：多主題、多語系與體驗收尾

#### 前端工作
- 完成全站主題切換細節校正。
- 補齊核心頁面的 `zh-HK` 與 `en` 文案。
- 補齊 loading、空狀態、錯誤狀態、無權限狀態。
- 進行細部視覺優化與響應式修正。

#### 後端工作
- 檢查 API 是否支援多語系基礎輸出需求。
- 清理不一致欄位命名與錯誤訊息。
- 補齊基礎限流、防刷與必要審計記錄。

#### 交付物
- 主題切換可用。
- i18n 骨架可用。
- 核心頁面達到可驗收品質。

### 階段 8：測試、UAT 與上線準備

#### 前端工作
- 完成主流程自測與回歸。
- 修復視覺、互動與跨裝置問題。
- 整理 UAT 清單與演示路徑。

#### 後端工作
- 補齊正常路徑測試與關鍵回歸測試。
- 執行 `gofmt -w ./...` 與 `go test ./...`。
- 整理環境變數、部署步驟、回滾方案與巡檢清單。

#### 交付物
- 測試環境可完整演示二手一期閉環。
- 上線所需文件與腳本齊備。

## 6. 前端逐步實作計畫

### 6.1 Step 1：建立基礎工程與路由骨架
- 在 `web` 初始化 `Vue 3 + TypeScript + Vite`。
- 接入 `Vue Router`、`Pinia`、`Axios`、`Tailwind CSS`、`Ant Design Vue 4`、`vue-i18n`。
- 建立 `src/httpapis`、`src/model`、`src/pinia`、`src/router`、`src/stores`、`src/utils`、`src/components`、`src/views`。
- 建立全域 Layout、基礎 Header、基礎 Footer、404 頁與空白首頁。
- 完成標準：前端專案可正常啟動，具備最基本頁面切換能力。

### 6.2 Step 2：建立主題系統與設計 Token
- 先定義色彩、字級、圓角、陰影、間距、邊框等設計 token。
- 建立至少三套主題，例如 `default`、`warm`、`dark-neutral`。
- 實作全站主題切換機制，避免在元件內直接寫死色碼。
- 優先定義語意化 token，例如 `primary`、`surface`、`text`、`text-muted`、`border`、`success`、`warning`、`danger`。
- 完成標準：切換主題後，基礎版型、卡片、按鈕、表單樣式會同步變化。

### 6.3 Step 3：建立 i18n 骨架
- 接入 `vue-i18n`。
- 先建立 `zh-HK` 與 `en` 兩套語系檔。
- 建立共用文案鍵值規則，例如頁面標題、按鈕文案、表單標籤、錯誤提示。
- 在 Layout 與核心頁面預留語系切換能力。
- 完成標準：至少首頁與列表頁可切換語言，前端不再直接散落硬編碼文案。

### 6.4 Step 4：先做高保真頁面原型
- 使用 mock data 完成以下頁面原型：
  1. 統一入口頁
  2. 二手列表頁
  3. 二手詳情頁
  4. 登入頁
  5. 發布頁
  6. 我的發布頁
  7. 聊天頁
- 優先完成 desktop 與 mobile 版型。
- 先把資訊架構、主要操作流程、空狀態與錯誤狀態畫清楚。
- 完成標準：不依賴 Figma，也能完整演示二手一期的主要操作路徑。

### 6.5 Step 5：整理共用元件與頁面級元件
- 抽出可複用元件，例如 Header、搜尋列、篩選列、列表卡片、聯絡入口、聊天訊息氣泡、圖片上傳元件。
- 頁面專屬區塊放入 `views/<module>/components/`。
- 保持元件拆分以職責內聚為主，不為了拆而拆。
- 完成標準：頁面主要區塊不再全部堆在單一頁面檔案中，且仍易於理解。

### 6.6 Step 6：建立 API 層與 TypeScript 型別骨架
- 在 `src/httpapis` 建立對應 API 檔案。
- 在 `src/model` 建立對應資料型別，與後端 JSON key 保持一致。
- 建立 mock data 與真實 API 的切換邊界。
- 先整理一期會用到的型別：`User`、`Community`、`Listing`、`ListingImage`、`Chat`、`Message`。
- 完成標準：前端資料流已分離為頁面層、API 層、型別層，後續可平滑切換真實 API。

### 6.7 Step 7：接入第一輪真實 API
- 優先接入：
  1. 登入
  2. 會員資料
  3. 社區清單
  4. 二手列表
  5. 二手詳情
- 將登入頁、個人資料流程、列表頁、詳情頁從 mock 切到真實資料。
- 其餘未就緒流程暫時保留 mock。
- 完成標準：訪客瀏覽、會員登入、社區選擇、列表查詢、詳情查看可以使用真實資料閉環。

### 6.8 Step 8：接入第二輪真實 API
- 接入發布、編輯、我的發布、圖片上傳相關接口。
- 將發布頁與我的發布頁從 mock 切到真實 API。
- 串接阿里雲 `OSS` 上傳流程的前端部分。
- 完成標準：使用者可真實發布帖子、上傳圖片、查看自己的帖子列表。

### 6.9 Step 9：接入第三輪真實 API
- 接入聯絡方式權限接口。
- 接入聊天會話、訊息列表、發送訊息、已讀或未讀提示接口。
- 接入重新發布流程與過期狀態顯示。
- 完成標準：詳情頁聯絡、聊天頁互動、過期後重新發布形成閉環。

### 6.10 Step 10：前端收尾與驗收準備
- 補齊 loading、空狀態、錯誤狀態、無權限狀態。
- 檢查多主題與 i18n 是否覆蓋核心頁面。
- 修正 desktop 與 mobile 響應式細節。
- 整理 UAT 演示路徑與自測清單。
- 完成標準：前端達到可聯調、可演示、可驗收狀態。

### 6.11 前端當前不先做的內容
- 服務式住宅完整頁面
- 樓盤放售完整頁面
- 過度抽象的通用組件平台
- 搜尋推薦系統
- 高成本動畫與非核心視覺特效

## 7. 後端逐步實作計畫

### 7.1 Step 1：建立後端專案骨架
- 在 `http_service` 初始化 `Go` 專案與 `go.mod`。
- 建立 `cmd/server`、`internal/router`、`internal/handler`、`internal/service`、`internal/model`、`internal/middleware`、`internal/config`、`internal/database`、`internal/errcode`、`internal/logger`、`internal/utils`。
- 建立 `/api/v1/health` 健康檢查接口。
- 完成標準：後端專案可正常啟動，並可回傳健康檢查結果。

### 7.2 Step 2：完成配置、Logger、Errcode 與 Middleware 骨架
- 建立統一配置讀取。
- 建立統一 logger。
- 建立統一錯誤碼與回應格式。
- 建立 request id、recovery、request logging、auth 骨架中介層。
- 完成標準：專案具備一致的啟動方式、日誌格式與錯誤輸出口徑。

### 7.3 Step 3：完成資料庫初始化與 Migration
- 接入 `PostgreSQL` 與 `GORM`。
- 建立資料庫初始化流程。

## 9. 每階段驗收口徑

### 9.1 前端驗收
- 畫面不依賴 Figma 才能理解。
- 原型直接可演進為正式頁面。
- 主題切換不需重寫元件。
- 文案可切換語系。
- desktop 與 mobile 版面均可用。

### 9.2 後端驗收
- 所有接口統一走 `/api/v1`。
- 回應與錯誤口徑統一。
- 權限校驗不依賴前端判斷。
- 上傳流程基於阿里雲 `OSS`。
- 帖子生命周期可正確流轉。

### 9.3 系統驗收
- 訪客可瀏覽列表與公開詳情。
- 已登入會員可依規則聯絡賣家。
- `building_only` 內容受到保護。
- 發布、查詢、聊天、重新發布形成閉環。

## 10. 當前建議結論

- 此專案最適合採用「前端高保真原型先行，但直接落在正式 Vue 工程」的策略，而不是額外做一套純靜態原型。
- 後端不應等待前端頁面全部完成後才開始，而應同步完成骨架、資料模型與核心接口。
- 多主題與 i18n 應在一期最早階段建好框架，不可延後到聯調尾聲才補。
- 一期開發節奏應始終圍繞 `二手鄰里交易平台` 的最短閉環，避免三條業務線同時推進造成失控。
