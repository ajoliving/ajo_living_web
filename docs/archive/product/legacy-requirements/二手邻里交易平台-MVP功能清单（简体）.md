## 2. MVP 定义

### 2.1 一期目标
- 建立一个面向邻里住户的轻量级 C2C 二手交易子系统。
- 打通“浏览商品 -> 登录会员 -> 联系卖家 -> 卖家管理帖子 -> 自动过期 -> 重新发布”的基础闭环。
- 在统一频道体系中复用账号、消息、上传、生命周期和权限能力，避免单模块重复建设。

### 2.2 MVP 范围原则
- 只做支撑业务闭环的必要功能，不做重运营、重推荐、重交易履约的复杂能力。
- 以“邻里优先、低摩擦、可管理、可控风控”为第一优先级。
- 优先复用统一页面与公共能力层，不单独复制账号、消息、上传或状态机能力。

### 2.3 一期不追求的目标
- 不建设平台担保交易、在线支付、物流履约。
- 不建设复杂推荐算法、信用分体系、IM 多媒体消息。
- 不建设完整营销体系，例如优惠券、活动报名、直播卖货。

## 3. 用户角色与业务边界

### 3.1 用户角色
- 访客：可浏览公开商品，不可查看联系方式，不可发起联系。
- 注册会员买家：可查看受权限保护的联系方式，并通过 WhatsApp 或站内短讯联系卖家。
- 注册会员卖家：可发布商品、编辑商品、管理状态、重新发布过期帖子。
- 平台运营：可审核、下架、隐藏违规内容，并处理基础风险控制。

### 3.2 业务边界
- 本模块属于统一频道体系中的子模块之一，不作为独立站点拆分。
- 公共页面和公共能力应与楼盘放售、服务式住宅模块统一规划。
- 本模块强调“邻里限定”和“短周期高频信息”，其有效期、字段结构和联系逻辑与其他模块存在差异，但账号、权限和消息能力应共用。

## 4. MVP 成功标准

### 4.1 业务成功标准
- 用户可在前台完成公开浏览和邻里限定浏览。
- 登录会员可成功联系卖家。
- 卖家可独立完成发布、编辑、查看状态和重新发布。
- 平台可自动处理帖子过期，并保证过期内容不再出现在前台结果中。

### 4.2 交付成功标准
- 功能范围冻结后，可直接进入页面原型、数据模型和 API 设计阶段。
- 每个功能项具备明确页面承接点、状态规则和基本验收口径。
- MVP 范围与非 MVP 范围划分清晰，避免开发阶段持续扩张。

## 5. MVP 必做功能清单

### 5.1 公共能力复用

| 编号 | 功能项 | 范围级别 | 功能说明 | 验收要点 |
| --- | --- | --- | --- | --- |
| `C-MVP-01` | 手机号注册登录 | MVP 必做 | 复用统一会员系统，支持注册、登录、登出、Token 校验 | 未登录用户点击受限动作时，统一跳转登录页；登录成功后可回跳原页面 |
| `C-MVP-02` | 会员身份补充 | MVP 必做 | 用户首次进入本模块需补充所属大厦或屋苑信息，用于邻里可见性校验 | 用户资料中存在 `building_id`；未完善资料时不得查看邻里限定内容 |
| `C-MVP-03` | 登录墙与权限控制 | MVP 必做 | 联系方式、站内消息、Building-Only 内容均需通过会员校验 | 未登录或无权限用户不得通过前端源码或接口获取敏感信息 |
| `C-MVP-04` | 多图上传与封面图 | MVP 必做 | 复用统一内容发布能力，支持多图上传、封面图设置、图片排序 | 发布成功后详情页和列表页能正确展示封面图及图片集 |

### 5.2 前台浏览能力

| 编号 | 功能项 | 范围级别 | 功能说明 | 验收要点 |
| --- | --- | --- | --- | --- |
| `N-MVP-01` | 邻里交易列表页 | MVP 必做 | 提供本模块的商品列表承接页，展示封面图、标题、价格、分类、地区、发布时间、邻里标签 | 列表页可正常分页展示 `Active` 状态帖子，且不展示 `Expired` 内容 |
| `N-MVP-02` | 基础搜索与筛选 | MVP 必做 | 支持关键字、分类、价格类型、地区、排序、仅看同屋苑、仅看免费送赠等基础筛选 | 用户筛选后结果准确，支持重置筛选条件 |
| `N-MVP-03` | 商品详情页 | MVP 必做 | 展示商品基本信息、尺寸、描述、交收方式、图片和发布者身份标识 | 详情页需完整展示必填字段，并区分公开信息与会员可见信息 |
| `N-MVP-04` | 邻里限定可见性 | MVP 必做 | 支持 `Public` 与 `Building-Only` 两种可见范围 | 非同大厦会员不可查看 `Building-Only` 商品详情 |
| `N-MVP-05` | 状态标识与展示规则 | MVP 必做 | 在列表和详情页正确区分 `Active / Expired / Sold` 状态 | `Expired` 不在前台默认结果中出现；`Sold` 状态展示受控且不可继续联系 |

### 5.3 卖家发布与管理

| 编号 | 功能项 | 范围级别 | 功能说明 | 验收要点 |
| --- | --- | --- | --- | --- |
| `N-MVP-06` | 发布商品页 | MVP 必做 | 卖家可填写标题、分类、价格、新旧程度、尺寸、描述、交收地点、图片、可见范围、联系开关 | 表单校验完整，必填字段缺失时不可提交 |
| `N-MVP-07` | 编辑商品 | MVP 必做 | 卖家可编辑未过期或过期帖子的信息 | 编辑后更新时间刷新，前台展示同步更新 |
| `N-MVP-08` | 我的帖子管理 | MVP 必做 | 卖家可查看帖子列表，按 `Active / Expired / Sold` 分类管理 | 卖家可快速查看帖子状态、更新时间和过期时间 |
| `N-MVP-09` | 重新发布过期帖子 | MVP 必做 | 对过期帖子执行重新发布，允许同步修改价格或图片 | 重发成功后 `expire_at` 重置为新的 14 天，列表排序前移 |
| `N-MVP-10` | 软删除与下架 | MVP 必做 | 用户删除仅做软删除；卖家可主动标记为已售或下架 | 数据保留历史记录，不进行物理删除 |

### 5.4 沟通与消息

| 编号 | 功能项 | 范围级别 | 功能说明 | 验收要点 |
| --- | --- | --- | --- | --- |
| `N-MVP-11` | WhatsApp 联系 | MVP 必做 | 卖家可开启 WhatsApp；买家登录后可跳转 `wa.me` 发起联系 | 预设消息中包含商品标题和商品链接 |
| `N-MVP-12` | 站内短讯基础版 | MVP 必做 | 卖家可开启站内聊天；买家登录后发起基础文字会话 | 消息内容可持久化存储，会话可追踪最近消息和更新时间 |
| `N-MVP-13` | 新消息红点提醒 | MVP 必做 | 在“我的消息”或模块入口展示未读提醒 | 新消息到达后红点状态准确，已读后可消除 |
| `N-MVP-14` | 联系方式按卖家配置展示 | MVP 必做 | 卖家可选择 `WhatsApp / Chat / Both` | 若卖家仅开站内短讯，则详情页不得展示 WhatsApp 按钮 |

### 5.5 生命周期、风控与运营后台

| 编号 | 功能项 | 范围级别 | 功能说明 | 验收要点 |
| --- | --- | --- | --- | --- |
| `N-MVP-15` | 自动过期任务 | MVP 必做 | 系统按小时扫描过期帖子并更新状态 | `expire_at < 当前时间` 的帖子自动转为 `Expired` |
| `N-MVP-16` | 内容审核与人工下架 | MVP 必做 | 平台运营具备基础内容审核、隐藏、下架能力 | 运营下架后前台不可见，后台保留审计痕迹 |
| `N-MVP-17` | 敏感信息保护 | MVP 必做 | 联系方式不得对访客明文暴露，接口需做会员校验与限流 | 不得通过抓包或未授权接口批量获取 WhatsApp 或电话信息 |
| `N-MVP-18` | 基础埋点与日志 | MVP 必做 | 记录发布、重发、联系、消息、下架等关键动作日志 | 核心动作具备最小可追踪性，便于排错和运营复盘 |

## 7. 明确不纳入一期 MVP 的范围

- 在线支付、担保交易、平台抽佣结算。
- 运费模板、配送对接、物流跟踪。
- 多媒体聊天，例如图片、语音、视频消息。
- 信用评分、成交保障、身份深度认证。
- 智能推荐、个性化 Feed、复杂营销活动。

## 8. 关键页面承接关系

| 功能域 | 对应页面 |
| --- | --- |
| 浏览与筛选 | 邻里交易列表页、商品详情页 |
| 发布与管理 | 发布商品页、编辑商品页、我的帖子管理页、重新发布页 |
| 沟通与消息 | 商品详情页、聊天会话页、我的消息页 |
| 公共能力 | 登录注册页、会员资料完善页、我的中心页 |
| 运营支持 | 内容审核后台、帖子管理后台 |

## 9. 依赖与前置条件

### 9.1 依赖统一能力层
- 统一账号与登录体系。
- 统一图片上传与文件存储能力。
- 统一消息中心或站内信基础设施。
- 统一状态字段、生命周期字段和软删除约定。

### 9.2 前置设计产物
- 页面清单与页面流转图。
- 数据模型与表结构设计。
- API 清单与权限矩阵。
- 页面原型与字段级校验规则。

## 10. 当前结论

- 二手邻里交易平台一期 MVP 已可定义为“轻量发布 + 邻里浏览 + 会员联系 + 帖子管理 + 自动过期 + 基础运营控制”。
- 从标准产品流程看，本清单可以作为后续原型、技术方案、数据库设计和测试用例拆解的基线文档。
- 若要继续按大企业规范推进，下一步应在此基础上补齐页面清单、流程图、字段字典、权限矩阵和 API 规范。
