# AJO Living 通知与会话系统 UI 优化方案

## 现状分析

### 当前问题
1. **信息架构混乱**：通知中心把「訊息管理」和「大廈群聊」分开，但两者本质都是会话
2. **视觉不统一**：群聊列表项和普通聊天列表项使用不同的样式
3. **功能错位**：普通用户在聊天页面看到大量管理功能（成员列表、禁言、剔除等）
4. **交互割裂**：群聊打开后显示成员管理区域，破坏聊天连续性
5. **职责不清**：管理功能散落在普通聊天页面，应该集中在管理端

### 优势保留
1. 左中右三栏布局清晰
2. 现有设计系统（颜色、间距、圆角）统一
3. 响应式处理基础良好
4. API 接口完整

## 设计理念

### 核心原则
1. **统一性**：所有会话使用相同的视觉语言和交互模式
2. **简洁性**：移除冗余元素，专注核心功能
3. **层次性**：通过微妙的视觉差异区分不同类型会话
4. **一致性**：桌面端和移动端保持体验连贯
5. **专业性**：管理功能归属管理端，普通页面保持纯净

## UI 优化方案

### 一、通知中心重构

#### 1.1 导航结构
```
會話區域
├── 訊息           (合并：一对一聊天 + 大厦群聊)

通知區域  
├── 全部通知
├── 優惠通知
├── 物業通知
└── 支付通知
```

**移除**：独立的「大廈群聊」导航项

#### 1.2 视觉设计
- **导航项**：保持现有样式，统一间距 12px
- **图标**：会话用 `message`，通知用各自的类型图标
- **徽章**：未读数量使用品牌色，已读使用灰色
- **分组标题**：使用 11px 大写字母，淡化处理

### 二、会话列表统一

#### 2.1 列表项结构
```
┌────────────────────────────────────┐
│ [头像]  对话名称            [时间] │
│         最后消息预览        [未读] │
└────────────────────────────────────┘
```

**统一元素**：
- 头像：40px 圆形（一对一用用户头像，群聊用建筑图标或多人图标）
- 名称：14px 粗体
- 时间：12px 灰色，右对齐
- 预览：13px 灰色，单行截断
- 未读：红色圆点或数字徽章
- 间距：上下 12px，左右 16px
- 分隔线：1px，颜色 `rgb(var(--color-border) / 0.5)`，左右留白 16px

#### 2.2 群聊特殊标识
```
┌────────────────────────────────────┐
│ [建筑图标] 大廈名稱         [时间] │
│ 🏢 15名成員                 [未读] │
└────────────────────────────────────┘
```

**差异化**：
- 头像使用建筑图标背景色
- 预览区显示「🏢 XX名成員」
- 悬停时显示完整大厦名称

#### 2.3 交互状态
- **默认**：背景透明
- **Hover**：`background: rgb(var(--color-surface-raised))`
- **Active**：`background: rgb(var(--color-primary) / 0.08)`，左侧 3px 品牌色竖线
- **Focus**：2px 品牌色描边

### 三、聊天详情页优化

#### 3.1 页面结构（统一）
```
┌─────────────────────────────────────┐
│  标题栏：对话名称 + 操作按钮          │
├─────────────────────────────────────┤
│                                     │
│  消息滚动区域                        │
│  （所有会话类型统一）                 │
│                                     │
├─────────────────────────────────────┤
│  输入区域 + 发送按钮                  │
└─────────────────────────────────────┘
```

#### 3.2 标题栏设计
**一对一聊天**：
```
[< 返回]  用户名称                    [•••]
```

**大厦群聊**：
```
[< 返回]  大廈名稱 (15名成員)          [離開群聊]
```

**移除**：
- 成员管理面板
- 禁言、剔除、封禁按钮
- 加入申请审核区域

#### 3.3 群聊功能简化
**普通用户可见**：
- 查看消息
- 发送消息
- 离开群聊按钮（标题栏右侧，次要样式）

**移至管理端**：
- 查看成员列表
- 禁言、解除禁言
- 剔除、封禁、解除封禁
- 审核加入申请
- 邀请新成员

### 四、管理端群聊管理

#### 4.1 页面保持
继续使用表格布局展示所有群聊：
```
┌──────────────────────────────────────────┐
│ 大廈編號    成員數    未讀數    操作      │
├──────────────────────────────────────────┤
│ BLD001     15        3        [查看成員] │
│ BLD002     8         0        [查看成員] │
└──────────────────────────────────────────┘
```

#### 4.2 成员管理弹窗
点击「查看成員」打开 Modal：
```
┌──────────────────────────────────────┐
│  大廈 BLD001 群聊成員           [X]  │
├──────────────────────────────────────┤
│  [邀請用戶]                          │
├──────────────────────────────────────┤
│  用户名    角色    状态    操作       │
│  张三      成员    正常    [禁言][移除]│
│  李四      成员    禁言中  [解除][封禁]│
└──────────────────────────────────────┘
```

### 五、视觉系统

#### 5.1 颜色
- **品牌色**：`rgb(var(--color-primary))`
- **文本主色**：`rgb(var(--color-text))`
- **文本次要色**：`rgb(var(--color-text-muted))`
- **背景**：`rgb(var(--color-surface))`
- **抬高背景**：`rgb(var(--color-surface-raised))`
- **边框**：`rgb(var(--color-border))`
- **分隔线**：`rgb(var(--color-border) / 0.5)`

#### 5.2 圆角
- **卡片**：8px
- **按钮**：6px
- **输入框**：6px
- **头像**：50%

#### 5.3 间距
- **section gap**：24px
- **card padding**：16px
- **list item padding**：12px 16px
- **button padding**：10px 16px

#### 5.4 字体
- **标题**：16px 粗体
- **正文**：14px 常规
- **次要文本**：13px 常规
- **小文本**：12px 常规
- **导航标签**：11px 大写粗体

### 六、响应式设计

#### 6.1 桌面端（≥768px）
- 三栏布局：240px + flex + 360px
- 左侧导航固定
- 中间会话列表可滚动
- 右侧详情区域可滚动

#### 6.2 移动端（<768px）
- 单栏布局，通过路由切换
- `/notifications` → 导航 + 会话列表
- `/notifications/chat/:id` → 聊天详情（全屏）
- 底部导航不遮挡输入框
- 输入框聚焦时自动滚动到可见区域

## 实施步骤

### 第一步：重构通知中心导航
1. 移除「大廈群聊」独立导航项
2. 「訊息管理」改名为「訊息」
3. 调整导航项顺序和间距

### 第二步：统一会话列表
1. 合并一对一聊天和群聊到同一个列表
2. 统一列表项样式（头像、名称、预览、时间、未读）
3. 添加群聊特殊标识（建筑图标 + 成员数）
4. 统一分隔线和间距

### 第三步：简化聊天详情页
1. 移除群聊成员管理面板
2. 移除禁言、剔除、封禁按钮
3. 只保留「离开群聊」按钮在标题栏
4. 统一所有会话的标题栏、消息区、输入区样式

### 第四步：完善管理端
1. 保持表格布局
2. 优化成员管理 Modal 样式
3. 确保管理功能完整可用

### 第五步：响应式优化
1. 移动端单栏布局
2. 输入框不被底部导航遮挡
3. 聚焦时自动滚动

### 第六步：测试验证
1. TypeScript 类型检查
2. 构建验证
3. 桌面端测试
4. 移动端测试
5. 深链接测试

## 预期效果

1. **信息架构清晰**：会话就是会话，通知就是通知
2. **视觉统一**：所有会话列表项使用相同样式
3. **交互简洁**：普通用户只看到必要功能
4. **职责明确**：管理功能集中在管理端
5. **体验流畅**：桌面和移动端都保持良好可用性
6. **可维护性高**：代码结构清晰，职责明确
